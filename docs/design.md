# 設計メモ

## 決定事項（2026-10-30）

| 項目 | 決定 |
|---|---|
| 位置づけ | 高校生による作品としての試作。実在の利用者データは扱わない |
| リポジトリ | GitHub 公開リポジトリ |
| 本人確認・団体審査 | 書類アップロード → 管理者が目視で審査 → 承認／却下（理由つき） |
| 対象地域 | 愛知県（名古屋市16区＋その他）から開始 |
| 資金支援 | 画面と設計のみ。法的確認が完了するまで決済・申込は無効（DBでも申込を拒否） |

## 権限の考え方

画面でボタンを隠すのは「使いやすさ」のため。本当の制限はすべてデータベース側（RLS・トリガー・関数）で行う。

| 操作 | できる人 |
|---|---|
| 募集の作成 | 審査承認済み・停止されていない子ども食堂 |
| 支援の申込 | 審査承認済み・停止されていない企業／地域住民（自分の募集には不可） |
| 申込の承認・見送り・完了 | その募集を出した子ども食堂 |
| 申込の取り消し | 申込者本人（確認待ち・承認後のみ） |
| 連絡先（電話・住所）の閲覧 | 本人、管理者、承認済みの申込でつながった相手 |
| 審査の承認／却下、募集の非公開化、利用停止 | 管理者（専用関数のみ。操作履歴に自動記録） |
| 管理者の任命 | データベース所有者が SQL で手動設定のみ |

テスト：`npm run test:db` で54項目を自動確認（`supabase/tests/rls.test.mjs`）。

## 食品の安全確認

提供申込時に必須：品名・数量・賞味期限／消費期限の区別と日付・保存状態（常温／冷蔵／冷凍）・アレルゲン（特定原材料8品目）・未開封であること・受け渡し方法。
期限切れ・開封済みの申込はデータベースが受け付けない。

## 未成年の利用

- 登録時に年齢区分を確認。18歳未満は保護者同意がないと登録できない（DB制約）
- 未成年は「地域住民」区分のみ。子ども食堂・企業の代表にはなれない
- 未成年は資金支援不可
- 保護者の氏名・連絡先は非公開テーブルに保存

## 退会（アカウント削除）時の個人情報処理（実装済み：`delete_my_account()`）

データベース関数（security definer）で次を実行する。Edge Function や service_role キーは不要。

1. 進行中（確認待ち・承認済み）の申込がある場合は退会を止め、先に完了か取り消しを求める
2. 本人確認書類をストレージから削除
3. `profile_private`（連絡先）を削除
4. `profiles` の表示名を「退会済みユーザー」に置き換え、ログイン情報（auth.users）を削除
5. 支援の記録は件数・日付・種類のみ残し、個人が特定できない形にする
6. 削除したことを操作履歴に記録

## 資金支援を有効にする前に必要なこと（未着手）

- 運営団体の決定（学校・NPO等）と、寄付の受け取り主体の整理
- 決済事業者（例：Stripe等）の選定と審査
- 返金方針、領収書の発行、会計処理の担当者
- 不正利用（盗用カード等）への対策
- 法律の専門家による確認
